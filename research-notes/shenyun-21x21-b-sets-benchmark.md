# 21×21：以单字 B 集合首选率为先的对照口径

本轮先冻结**单字候选首选损失**，然后才比较 R9 的速度、负载、M/D；多字词的 B 集合只做观察。用户所说的 B 是一个辅助键集合，**不是**“加一笔、加两笔”。方案须锁定实体辅助键 AVUIO，引擎音调顺序 IVUAO。

## 四条单字路径

| 实际输入路径 | 第一个 B | 第二个 B | 计算来源 | 相对 S005 的门槛 |
|---|---|---|---|---:|
| 键道 `IR+B` | 拆分笔/形码首键 | — | `snow_jiandao_chaifen.dict.yaml` + `radical_jiandao.txt`；R11 `snowshape` | < 5.048128409% |
| 键道 `IR+B1+B2` | 拆分笔/形码首键 | 同一字拆分笔/形码次键 | R11 `C4-Snow` (`IRXX`) | < 1.347402148% |
| 三拼 `IR+B` | 字的声调 | — | R11 `C3` (`IRT`) | < 5.378529201% |
| 三拼 `IR+B1+B2` | 字的声调 | 字的**纯笔画首键** | `rime-stroke/stroke.dict.yaml`，按 `lua/snow/shape_filter.lua` 的运行时映射 | 暂测 < 1.920934871% |

二字词均从 `IRIR` 开始，接 B 时**先次字 B2，后首字 B1**；键道对应次字、首字的笔/形码，三拼对应次字、首字的声调。见 [`code_navigator.lua`](../lua/snow/code_navigator.lua) 的字位说明。二字词的首选率保留作结果和相关性检验，不用于本轮硬筛；单字好并不在数学上保证二字词必然更好。

四项统一使用 R11 的 Common8095 单字行、字频和“同码组中只有最大字频的一条算首选”的口径。真实键数可能是 3 或 4；指标按追加 **B 集合个数** 分，不按物理笔画数、裸二键唯一码数或加权音节损失分。保留 399 唯一码数作诊断护栏，不让它代替任何一条单字路径。每项须严格低于同项 S005；在达标子集内，先比 S2/v4/v5/v6、主行和峰值负载、日常 MX，再降低 M、D。建议记录四项超越基线的最小相对余量，用来区分险过门槛和留有缓冲的候选，不把四项平均后掩盖其中某一项失守。

## 冻结校验和目前的种子

[只读基准脚本](../scripts/research/benchmark_shenyun_21x21_b_sets.py)读取本仓库的笔画字典及 R11 原始重放数据。它先逐字核对 R11 `snowshape` 与仓库 8,095 条常用字的键道拆分码完全一致，再独立复算 S005、R9 的键道双 B (`C4-Snow`) 和三拼首 B (`C3`)，误差 < 1e−12；最后计算缺失的键道首 B 与三拼声调加纯笔画。其 [逐端点记录](data/shenyun-21x21-b-sets-benchmark.json) 对上一轮 226 个可表示状态审计：键道两项均胜 S005 的有 39 个；按笔画字典首条码作三拼纯笔画时，四项都胜的暂有 5 个。这是有界端点而非不可行性证明。

其中 `B21-65881cec01de` 是值得继续复核的 M43/D3 种子：四项非首选依次 4.84535%、1.32934%、5.33573%、1.88763%，同项 S005 是 5.04813%、1.34740%、5.37853%、1.92093%；搜索因子预计 S2 71.183 ms、v5 10.4690、v4 10.6966。后续须用原始 20 合同引擎补算，不能把搜索因子当作最终记录。

**三拼第二 B 尚属诊断指标。** 纯笔画字典对 Common8095 中有字频的字均有覆盖，但部分字有多个笔顺候选；上述数字暂取字典首条码。脚本另保存“各首笔码均可接受”的敏感性对照；不同候选间会新增竞争关系，因此该指标不一定比只取首条码更低，不能当作正式候选排序。 五个暂时跨四项门槛的端点在这一额外诊断口径下，三拼双 B 也仍低于对应 S005；这只检查编码桶，尚未复核真实 Rime 候选排序。`snow_sanpin_bihua.schema.yaml` 是反查用，字母次序与 `shape_filter.lua` 实际过滤映射不一致：正式筛选按运行时的 `hspnz → viuoa`，并需在 GitHub Actions 的真实 Rime 候选测试中核对多笔顺和首选顺序。冻结该合同、跑通 S005/R9 两个实机基准后，才把暂测的第四条数值升格为硬门槛。
