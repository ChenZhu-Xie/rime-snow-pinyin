# 前插与追加字实验

实验保持现有 `;` 追加「的」，比较 `/` 追加或前插「了在不与是有我着对把被过地得中上下为以和也就都」23 个字。另设生产配置、禁用 `/`、禁用 `;` 三个对照，总计 49 个变体。参与方案为四拼、兰道、兰拼、鹤道、鹤拼、莲道、鹮道、键道、三拼；清韵的标点编码语义不同，外部方案也不纳入这次功能替换。

## 比较口径

复用修正四拼单字编码后的冻结源码 `output/sipin-production-fix/source/`，读取原长语料缓存和路径。生产源码逐文件 SHA-256 必须与原评测清单一致；生产变体在每份语料上的总键数和选重数必须完全复现，才允许生成比较结果。缺失的前缀观测通过隔离 librime DLL 补采并缓存。

每个替换变体先删除全部原 `/` 路径，保留普通「了」、已有整词短码和 `;` 路径，再加入新前插／追加路径。要求基础候选尚未上屏、整条输入处理完成、首选文本与基础词一致。单独按 `/` 输出目标字；使用次数中单独按键次数另存为 `standalone`。因此总收益是整个键位替换的收益，不仅是有候选时的拼接收益。

原 5500 字和维基、新闻、酒店评论三份合计 36,235 字分别计算。每个方案各变体使用该方案原评测相同的可编码片段，跨方案覆盖不完全相同，不按各自总键数直接排跨方案名次。全篇重新切分，先最少选重再最少按键，包含 Space 和 Shift，不含标点；最优范围限于已枚举的路径。

「不知道」等已有整词短码始终参与竞争。例如四拼「我根本不知道」原路径为 `sgb_ | bwd`，共 7 键；前插「不」没有降低键数。「我觉得非常有趣」原路径 `sjd_ | fyfqa` 为 9 键，前插「我」改为 `jd/ | fyfqa` 为 8 键。这种局部收益必须与失去追加「了」的收益一并结算。

## 实际输出验证

只在 `output/prepend-experiment/validation-source/` 注入实验 Lua 处理器，不修改生产 Lua。处理器在原处理链之前截获 `/`，要求候选覆盖完整输入，调用 `snow.commit_text` 一次提交参数字与候选的拼接结果，再清空输入。前插和追加分别使用独立选项缓存。

所有入选的 `/` 编码都验证实际末键输出，而非只检查编码前缀。用同一个参数字「在」验证两种方向的字符串拼接，替换字不参与编码和候选生成；这不是把每个字单独部署一次的测试，也不是对原生 punctuator 追加实现的逐字验证。发现不完整上屏或文本不符时，剔除该方向的失败编码，重新切分，再验证新入选路径，直到没有失败。生产配置本身沿用原基准的实测结果。

## 运行与产物

在仓库根目录设置 `RIME_DLL` 和 `RIME_SHARED_DATA`，按方案串行运行，避免同时部署多个 librime 实例。以下为四拼示例；其余参数使用 `oc21-shape`、`oc21-tone`、`rc26-shape`、`rc26-tone`、`liandao`、`zhudao`、`classic-shape`、`classic-tone`。

```powershell
bun scripts/experiments/benchmark-prepend.ts sipin
bun scripts/experiments/validate-prepend.ts sipin
# 验证出现 rejected 时，重复上述两步，直到 rejected 为 0。
# 九方案均通过后：
bun scripts/experiments/summarize-prepend.ts
```

汇总、完整切分、候选池、末键探针、实际提交记录、DLL 缓存和编译副本均在 `output/prepend-experiment/`，由现有 Git 忽略规则排除，不提交大量切分结果。工具要求上述本地冻结源码和缓存存在，不能直接从干净 checkout 运行；准备过程见 [长语料评测](long-corpus-benchmark.md)。
