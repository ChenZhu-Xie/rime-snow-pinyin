# 四主码词长直选与 21×26 长词支持

用户已在对话中确认以下行为，并明确要求开始实现，先修复 21×26 基础能力。

## 行为合同

- 八套双拼生产方案接入，冰雪四拼、冰雪一拼、冰雪清韵与英拼不接入。`《`／`<`（Shift+逗号）选择当前四字词首选；`》`／`>`（Shift+句号）在 21×21 中先找五字及以上词，无则找二字词，在 21×26 中先找三字词，无则找五字及以上词。
- 类别优先，类内保持最终候选流顺序，从整个候选序列起点查找，不受当前页影响，不改空格和普通候选顺序。目标不存在时吞键并保留输入，禁止误选其他词长或追加标点。
- 只在中文 `abc` 段、光标位于当前段末尾、恰好四个主码时生效。21×21 补韵大写不计主码；补辅仍生效；第五字续写是新主码，不再触发。范围外保留原标点行为。
- 原生长词补全允许参加选择；短片段候选、临时整句和功能命令不参加。选择使用 Rime 正常选词与上屏路径，保留学习、缓冲和统计。
- 21×26 四声母提供原生五字及以上补全；四声母后大写声母继续五字及以上简拼，支持七字和更长词。小写第五键保留四码顶，已有辅码继续按原合同追加。
- 不修改冻结声韵映射、五辅语义、各词长辅序、固顶、版本号及无关方案。所有 Mira 与原生 Rime 验证只能在推送后的 GitHub Actions 运行。

## 已选方法

讨论过「两种词长混合按原排名选择」和「指定类别优先、另一类别兜底」；用户选择后者，并确认两类布局使用相反的 `》` 优先级。用户也确认四主码限制与补辅后仍可用。

21×26 继续复用现有 `shenyun` 翻译器与辅助码逻辑。四声母和长词采用不含填充分隔符的查询，避免代理码长度阻止 librime 启动词补全；查询结果仍显示逐字预编辑。大写续写在输入中保留为独立声母标记，查询时转小写，这使普通小写顶屏与显式长词续写保持可区分。

词长直选使用独立处理器，位于 `popping` 前，读取当前最终菜单，以标准 Rime 选择接口确认候选。四主码识别独立于字数：21×26 的二字全码和三字 AAAU 都是四主码；单字四辅或声声空桶四辅不是四主码。

## 验证

纯 Lua 测试覆盖真实翻译器和处理器的边界、完整消耗判定、长补全、类别优先、跨页、缺类、键修饰、缓冲和原标点退回。静态测试覆盖八套接入及处理器顺序。Mira 用例覆盖三个 21×26 长词入口与八套直选代表用例，两种 librime 同时验证。性能语料追加长补全、大写续写与直选，沿用统一预算。
