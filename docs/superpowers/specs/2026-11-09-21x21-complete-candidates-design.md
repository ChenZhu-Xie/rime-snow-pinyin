# 21×21 四码联合桶完整候选设计

## 目标

冰雪健道、冰雪键道、冰雪弎拼、冰雪三拼在顶功模式下，将四码联合桶限定为完整消耗当前音码的二字词和四字及以上简拼候选，不把只消耗第一个音节的单字候选混入其中。二字词与四字词继续按原生质量和用户词频自由竞争，不增加逐页词长配额。

## 行为约束

- 顶功模式的四码音码候选必须完整消耗当前输入；追加辅码后仍不得重新放入只匹配某个音节的单字候选。
- 冰雪健道、冰雪键道的主翻译路由只在非缓冲的顶功模式要求完整消耗；整句模式和缓冲模式保留原生前缀候选能力。
- 冰雪弎拼、冰雪三拼的二字词代理路由在非缓冲的顶功模式只接受完整二字词；缓冲模式保留选择单字片段来造词的能力。
- 学习词置顶只提升完整消耗当前音码的候选；前缀候选既不因已有用户词身份上移，也不以整个未消费输入写入用户词典。
- 不给四套 21×21 方案引入 `length_balance`。原生上游没有逐页均分二字词和四字词的算法；动态调频继续由原生用户词典语义及本仓库的跨路由学习恢复逻辑负责。
- 冰雪简道、冰雪散拼现有 21×26 词长柔性平衡保持不变。

## 验证

- Lua 单元测试覆盖完整候选判定，以及学习排序不得提升前缀用户候选。
- 四套方案的 Mira 场景覆盖四码二字词输入不出现单字候选；冰雪弎拼继续覆盖缓冲造词。
- 本机只运行静态、Lua 单元和生成/语料检查；Mira 场景按仓库约定推送后由 GitHub Actions 执行。
