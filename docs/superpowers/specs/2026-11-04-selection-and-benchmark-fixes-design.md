# 单字定字、方案部署与 benchmark 策略修复设计

## 意图

修复九个发布方案的单字定字行为、本机过期部署导致的方案旧名称和经典方案失效，并让十方案报告工具链遵守“先避免选重、再缩短实际按键、首选即停”的测量口径。

## 行为规格

- 九个发布方案中，当前候选只有一个汉字时，`[` 上屏两次该字，`]` 上屏该字后再加“得”；当前候选为多字词时，`[` 只上屏首字，`]` 只上屏末字。
- benchmark 的路径排序依次为选重次数、总实际按键、标准码字符数、分词段数、固顶命中、Space、Shift；因此不会为了少一个 Space 而在已经首选的标准码后继续补辅助码。
- 同一字词只要存在第一候选编码，就排除它的第二、第三候选编码；完全不存在第一候选编码时，才保留第二、第三候选作为兜底。
- 结构略码只参与实际启用 `snow.abbreviation` 的冰雪四拼、冰雪简道和冰雪散拼。当前六条仓库内重算轨中只有冰雪简道、冰雪散拼启用结构略码；冰雪健道、冰雪弎拼、冰雪键道、冰雪三拼只使用大写补韵。
- 四条外部冻结轨必须声明“空白用户词典、关闭调频、逐标准码检查首选并在首次成为首选时停止”的审计合同；缺少合同的旧冻结输入直接报错，不再静默生成看似可比较的十方案报告。
- 本轮不重生成 `reports/`，不运行 GitHub Actions，不改版本号与 release tag。

## 根因

- 仓库 schema 已使用冰雪键道、冰雪健道、冰雪简道、冰雪三拼、冰雪弎拼、冰雪散拼等现名，但本机 `build/` 仍保留旧编译名称且没有两个经典方案的编译产物；这是未重新部署造成的本机状态问题。
- `lua/snow/select_character.lua` 仅在候选长度大于一时处理 `[`/`]`，冰雪一拼也未挂载该处理器；冰雪四拼、冰雪简道、冰雪散拼的 `[` 单字重复此前由略码处理器偶然覆盖。
- 两个报告生成器把第二、第三候选与第一候选放在同一按键成本目标中，并在 Space 之前偏好可顶屏的更长编码；它们还无条件给六条重算轨生成结构略码。
- 十方案报告中的冰雪四拼、冰雪清韵、声笔小鹤、小鹤来自外部冻结回放，旧输入没有可验证的候选状态合同。

## 方案选择

采用“运行时行为归一 + 共用 benchmark 策略模块 + 冻结输入失败关闭”。单字特殊行为统一放入 `select_character.lua`，冰雪一拼按九方案处理器顺序挂载它；benchmark 的候选筛选和动态规划比较规则提取为两个报告生成器共用的库；冻结回放用显式审计标记阻止旧文件继续混入。

未采用仅修改报告文本或为示例硬编码替换的方式，因为这不能修复后续语料；也未在本轮重写四条外部方案的完整编码器，因为其中声笔小鹤和小鹤不属于本仓库，缺少可维护的本地运行合同。

## 验证

- 先给九份 Mira spec 增加单字 `[`/`]` 用例并确认失败，再修改 Lua 与冰雪一拼处理器配置使其通过；多字定字现有用例继续通过。
- 给 benchmark 共用策略增加小型纯数据单元测试，覆盖选重优先级、首选截断、最短标准码、21×21 禁用结构略码和选重信息在派生略码中的保留。
- 给冻结输入合同增加缺标记失败、正确标记通过的单元测试，不读取或生成正式 reports。
- 运行 TypeScript 格式、类型与 corpus 单元测试，运行九方案本地 Mira 测试，最后部署小狼毫并检查 `build/default.yaml` 的方案列表、六个现名以及两个经典 schema 编译产物。
