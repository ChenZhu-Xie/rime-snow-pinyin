# 神韵固顶候选语料与碰撞测量设计

## 目标

本阶段建立一个可重复生成、可追溯、默认不进入 Git 的固顶候选语料空间，并提供神韵与原冰雪键道在常用二字词、四字词上的编码碰撞对比。

本阶段不自动修改神韵现有二简、630 或单字固顶表，也不实现自动选优。后续的“受约束自动选优”只消费本阶段产出的规范化证据。

## 范围与原则

- 收集冰雪键道/三拼、星空键道、星猫键道、天行键及其他键道衍生方案。
- 收集墨奇/万象、魔然、品度双拼、简道鹤、极速小鹤及声笔小鹤等非键道方案。
- 只读取方案发布的静态词典、固顶表、简码表和必要的编码规则。
- 排除 `userdb`、同步数据、用户词典、私人短语、日志和构建产物。
- 不修改被扫描的本地仓库；有未提交改动的仓库也只读访问。
- 原始缓存、规范化语料和详细报告统一写入已被 `.gitignore` 忽略的 `cache/`。
- Git 只保存来源清单、解析与测量程序、格式说明、测试和精简统计摘要。

## 总体结构

```text
config/fixed-corpus-sources.yaml      # 受版本控制的来源清单
scripts/fixed-corpus/                 # 采集、规范化、汇总和测量程序
scripts/fixed-corpus/test/            # 小型合成夹具与单元测试
cache/fixed-corpus/                   # 全部忽略
  repositories/                       # 缺失公共来源的浅克隆缓存
  normalized/<source-id>.jsonl        # 每个来源的规范化记录
  corpus.jsonl                        # 汇总记录
  provenance.json                     # commit、文件哈希和生成参数
  reports/summary.json                # 完整统计
  reports/collisions.json             # 完整碰撞数据
reports/fixed-corpus-summary.md       # 可提交的精简摘要
```

生成目录可整体删除并重建，不承载人工维护状态。

## 来源清单

来源清单中的每个来源具有以下字段：

- `id`：稳定的来源标识。
- `name`：人类可读名称。
- `family`：谱系家族，用于标记共享祖先的衍生方案。
- `adapter`：解析器类型。
- `localPaths`：Windows 本地路径候选，按顺序探测。
- `repository`：本地不存在时可使用的公开 Git 仓库。
- `ref`：可选分支、标签或提交。
- `include` / `exclude`：静态文件白名单与隐私/产物黑名单。
- `licenseHint`：仅用于提示人工核验，不替代上游许可证。

本地路径存在时直接只读扫描；否则把公开仓库克隆到 `cache/fixed-corpus/repositories/`。采集程序不对现有本地来源执行 `pull`、`reset` 或清理。

首批来源包括：

- 当前仓库的冰雪键道、冰雪三拼和神韵固顶表。
- 星空键道 `xkinput/KeyTao` 及可确认的公开衍生方案。
- 星猫键道 `hugh7007/xmjd6-rere`。
- 天行键 `wzxmer/rime-txjx`。
- 墨奇/万象本地仓库 `rime-moqi-wanxiang-schemas`。
- 魔然 `rimeinn/rime-moran`，必要时补充魔龙等同族方案。
- 品度双拼本地仓库 `rime-pindu-double-pinyin`。
- 简道鹤本地仓库 `rime-JDhe`。
- 极速小鹤本地仓库 `rime-fast-xhup`。
- Rime 用户目录中的声笔小鹤静态方案文件，但不读取个人数据。

新增方案只需扩展清单或新增解析适配器，无需改动汇总格式。

## 规范化记录

每行 JSON 表示一项“某来源在某编码位置推荐某字词”的证据：

```json
{
  "schemaVersion": 1,
  "sourceId": "sbxh",
  "family": "shengbi",
  "sourcePath": "sbxh.dict.yaml",
  "sourceRevision": "sha256-or-git-commit",
  "line": 42,
  "word": "一些",
  "originalCode": "yi'x",
  "normalizedCode": "yix",
  "wordLength": 2,
  "codeLength": 3,
  "category": "shortcut",
  "level": "three-code",
  "rank": 1,
  "weight": null,
  "derived": false,
  "metadata": {}
}
```

关键约束：

- 保留 `originalCode`，规范化不能破坏追溯能力。
- `normalizedCode` 只移除明确属于分隔/标记的符号，不猜测未知语义。
- 同一词在同一来源的不同编码分别留记录。
- 完全相同的重复行可去重，但不同来源、行号、顺位或派生方式不能折叠。
- 无法可靠解析的记录进入诊断统计，不静默丢弃。

## 解析适配器

第一阶段提供以下通用适配器：

1. `rime-table`：解析带显式编码和可选权重的 Rime 词典表。
2. `ordered-fixed`：解析“一码后跟多个有序候选”的固顶文件。
3. `custom-phrase`：解析 `词<TAB>码` 及 `/`、撇号等方案标记。
4. `encoder-derived`：读取字符码表和 Rime `encoder/rules`，为只有词条而无显式词码的方案生成派生码。
5. `plain-word-list`：只保留词频/顺位证据，不伪造编码。

方案特殊差异尽量通过清单参数表达；只有语法确实不同才新增专用适配器。

## 家族与来源独立性

本阶段不计算自动选优分数，但提前保存 `family`：

- 同一祖先词表的多个 fork 是多份来源证据，不是多份独立语言共识。
- 后续选优可分别查看“来源覆盖数”和“独立家族覆盖数”。
- 当前汇总同时给出原始记录数、来源去重词数和家族去重词数，避免数据规模造成误导。

## 隐私与安全边界

用户 Rime 目录采用白名单：只允许清单明确列出的 `sbxh` schema、dict 和 fixed 文件。无论文件名如何匹配，以下内容始终拒绝：

- `*.userdb*`
- `sync/`
- `user.yaml`、`installation.yaml`
- `*.custom.yaml` 和未明确列入来源清单的 `custom_phrase*`
- 日志、备份和构建目录

报告只记录被允许文件的相对标识和哈希；不把用户主目录绝对路径写入可提交摘要。

## 碰撞测量口径

### 共同词集

从当前 `rime-snow-pinyin` 自带词典读取词条与权重，分别建立二字词和四字词评测集。两个布局使用完全相同的词集、读音展开和词频权重。

为避免单个 Top-N 阈值左右结论，报告多个档位，例如 Top 500、1,000、2,000、5,000、10,000 以及全部可编码词。实际档位会根据可用词数截断并明确标注。

### 对比布局

- 神韵：当前 NF3-21X21-M40-44 / “零飞键道·神韵 v1”的规范编码。
- 原冰雪键道：迁移前的原始双拼映射。

原冰雪键道的 `derive` 规则可能产生多个可接受拼写。测量器必须把 `xform` 与 `derive` 区分：

- `canonical`：主变换路径生成的规范编码。
- `accepted`：输入法实际接受的全部派生编码集合。

两种口径分别报告，不能把 `derive` 错当成覆盖式替换。

### 指标

每个词频档位和布局至少输出：

- 可编码词数与覆盖率。
- 二字词内部、四字词内部的重码桶数、受影响词数、唯一编码率和最大桶大小。
- 二字词与四字词之间的四码交叉碰撞数、受影响词数和示例。
- 非加权比例与按词频权重计算的碰撞质量占比。
- 最严重碰撞桶及其中词条、读音、编码、权重。
- 神韵相对原冰雪键道的绝对差和相对差。

“冲撞严重程度”以多项指标呈现，不压缩成一个缺乏解释力的总分。

## 命令接口

脚本包提供三个稳定入口：

```powershell
npm run corpus:collect
npm run corpus:measure
npm run corpus:all
```

- `collect`：探测/获取来源，解析并生成规范化语料与摘要。
- `measure`：只使用当前项目词典和布局生成碰撞报告。
- `all`：顺序执行二者。

附加 CLI 参数允许覆盖缓存目录、本地来源根目录和离线模式。默认命令在缺少某个可选来源时继续处理其他来源，并在摘要中显著列出缺失项；必需的当前仓库来源缺失则失败。

## 验证策略

- 每个适配器使用最小合成夹具测试头部、注释、候选顺位、权重和异常行。
- 隐私测试确保用户词库与 `custom_phrase` 不会被宽泛 glob 意外读取。
- 幂等测试确保相同输入产生字节一致的 JSONL 和摘要（生成时间只进入单独 provenance 字段或被固定）。
- 家族统计测试防止 fork 数量被误当成独立共识数。
- 碰撞测试使用人工可算的小词集，覆盖二字内部、四字内部、跨词长和多读音。
- 旧布局测试必须验证 `derive` 展开为分支，而非覆盖主路径。
- 真实数据运行后抽查“一些”“冲着”“下了”等词在不同来源的证据，不把抽查词硬编码为选优结果。

## 非目标

- 不在本阶段决定“一些”“冲着”“下了”应占据哪个固顶位。
- 不按来源票数自动替换现有固顶。
- 不提交上游完整词典或缓存仓库。
- 不声称不同方案的简码层级具有完全相同语义；只规范化共同字段并保留原始元数据。

## 后续阶段

候选语料稳定后，再设计受约束自动选优系统。届时可把词频、现有用户肌肉记忆、来源/家族覆盖、码位价值、候选自然度和二简/630/单字空间互斥约束共同纳入求解，并要求每次变更输出可审计理由。
