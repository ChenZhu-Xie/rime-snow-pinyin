## 保存与地址映射

每个工作树完整保存源文件、报告、未跟踪文件、忽略文件和实际位于其中的缓存，另存对应 `.git/worktrees/<名称>/` 管理数据。原有依赖链接只记录路径、类型和目标，不跟随复制、不在冷盘重建；它们指向的主仓库依赖仍保留。冷盘快照内的 `.git` 文件是历史证据，不可直接作为活动工作树使用。

批次内 `worktree-snapshots/<名称>/` 对应历史检出，`git-admin/<名称>/` 对应其管理数据；`evidence/` 保存逐工作树审阅、staged／unstaged 补丁、原始 status 和一次性执行脚本。原路径与冷盘地址、HEAD、原分支、逐文件 SHA-256 和链接记录均写入两边相同的 `index.json`。旧报告中的绝对路径保持原样，查找时先按映射定位，不能因为报告写着旧地址便认为那里仍有文件。

`bundles/repository.bundle` 保存归档时主库的全部引用和 HEAD，包含保留的清韵分支及两个基准 HEAD 所属的 main 历史；三个子模块分别保存独立 bundle。每个 bundle 均在新建的空裸库中执行 `git bundle verify`，确认不依赖本机已有对象。这些 bundle 与未提交文件快照共同保存历史，不将代码 commit 误当作脏工作树的全部内容。

复制后先逐文件核对目标 SHA-256，再整批重读源与目标核对文件集合、长度、时间和 SHA-256，确认源未变化；每个检出移除前再次核验其文件及管理快照，最后由 Git 移除检出。链接只移除入口本身。源移除、文档提交和推送验证分开写回执；仅完成全部步骤后写 completion 回执。两边清单是元数据副本，实际 payload 只有冷盘这一份。

## 恢复

在独立且不存在的目录从主库 bundle 克隆，或在现有主库用 `git worktree add --detach <新目录> <完整HEAD>` 创建检出；需要时从子模块各自的 bundle 恢复它们的指定提交。按对应 manifest 恢复快照文件，排除旧 `.git` 指针，不覆盖新检出或子模块的管理信息。未跟踪文件需要从快照单独恢复，不能只应用 patch。

依赖按链接记录显式配置或重新安装，所有运行都在恢复副本中进行。部分旧基准检出的子模块链接存在历史路径问题，归档不修改其证据；恢复时初始化新的子模块，不能直接执行历史 `.git` 指针。冷盘保持冻结，恢复过程另记目标、基准批次和核验结果。

下一步可将已有批次的只读查询和核验整理成通用工具，再按需要扩展 plan、copy、finalize 与 restore；旧的一次性脚本仅作为批次证据，不直接重跑。当前没有为后续定时备份配置自动删除任务。
