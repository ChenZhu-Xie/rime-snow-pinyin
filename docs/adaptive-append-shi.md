# 单音节「×是」自适应上屏

`]` 对完整或不完整的单音节输入，查询所有兼容的标准二字词码，只取以「是」结尾的二字词。它不再先确定一个单字首选，再机械追加「是」。其他词即使被用户置顶，也不会作为输出。

每条标准词码通过当前引擎的完整翻译与过滤流程查询，保留学习、方案固顶、用户置顶及首选后置。该路只取最终菜单中的第一个匹配词，不会为了静态词频更高而改选该路后面的词。声母等不完整输入可能对应多条词码：合并时，匹配词的置顶优先，其次复用跨路候选的用户词优先级、学习权重与质量；完全相同的优先级按生成的词码顺序稳定取首项。不同词码不存在原生的统一菜单，该合并规则是此功能的明确约定。

`scripts/generate-append-shi.ts` 从现行单字词典读音及各方案代数生成 `lua/snow/append_shi_snow_*.txt`。文件只缓存输入与标准词码、读音约束，不缓存候选或排名；首次使用时只加载当前方案。修改拼写规则或单字读音后重跑生成器，`--check` 校验产物。四拼同时包含三码音节补 `o` 的入口，不接受 `mueaa` 一类非法扩展。词语路由用输入框内部编码，四拼与物理键入时的回头补码顺序不同；调辅双拼查询四主码，再按原始单音节的声调约束筛词。

查询期间不发送模拟按键，不提交任何试查结果；后置记录使用独立副本，避免试查改变真实状态或使不同查询路线互相影响。选定结果后通过原生选词和上屏流程提交，保留词语学习；输入统计只记录用户实际敲的键，试查耗时不会被误判为鼠标选词。

已有确认片段、光标回补、反查及独立形辅输入沿用原有以词定字。没有符合条件的二字词时恢复原输入及选中项，沿用原行为：单字追加「是」，多字取末字。`[`、`;`、`/` 的语义不变。

本地验证使用 `texlua spec/append_shi.test.lua`、`texlua spec/select_character.test.lua`、后置相关 Lua 测试及 `bun test ./scripts/generate-append-shi.test.ts`。真实方案测试在 GitHub Actions 的 `adaptive_append_shi` 部署中运行，不能用静态生成结果代替实际候选验证。旧的机械追加「是」研究及 benchmark 不能直接当作此功能的评测结果。
