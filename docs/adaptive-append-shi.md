# 单音节「×是」自适应上屏

`]` 先按当前选中候选分流：多字候选直接取末字，不做自适应查询；单字候选且输入为完整或不完整的单音节编码时，查询所有兼容的标准二字词码，只取以「是」结尾的二字词。进入查询后，不把首字锁定为当前单字候选；其他词即使被用户置顶，也不会作为查询结果。短码上选中「大家」时输出「家」，选中「嘚」时才进入查询，无匹配词则输出「嘚是」。

每条标准词码通过当前引擎的完整翻译与过滤流程查询，保留学习、方案固顶、用户置顶及首选后置。该路只取最终菜单中的第一个匹配词，不会为了静态词频更高而改选该路后面的词。声母等不完整输入可能对应多条词码：合并时，匹配词的置顶优先，其次复用跨路候选的用户词优先级、学习权重与质量；完全相同的优先级按生成的词码顺序稳定取首项。不同词码不存在原生的统一菜单，该合并规则是此功能的明确约定。

`scripts/generate-append-shi.ts` 从现行单字词典读音及各方案代数生成 `lua/snow/append_shi_snow_*.txt`。文件只缓存输入与标准词码、读音约束，不缓存候选或排名；首次使用时只加载当前方案。修改拼写规则或单字读音后重跑生成器，`--check` 校验产物。四拼同时包含三码音节补 `o` 的入口，不接受 `mueaa` 一类非法扩展。词语路由用输入框内部编码，四拼与物理键入时的回头补码顺序不同；调辅双拼查询四主码，再按原始单音节的声调约束筛词。

查询期间不发送模拟按键，不提交任何试查结果；后置记录使用独立副本，避免试查改变真实状态或使不同查询路线互相影响。选定结果后调用 `snow.commit_text` 直接上屏，再清空输入，不调用原生 `select` 或 `context:commit()`，因此不触发原生 Memory 或学习过滤器的提交通知。标准词码和简拼的既有学习、置顶影响本次选择，但 `]` 上屏不会反过来调频。输入统计与自由加词的文字收集仍收到直接上屏通知，只记录实际按键和输出字数。

路线同时记录生产词典是否存在对应「×是」二字词，用于跳过空查询；base、ext、tencent、user 词典变化后也须重新生成。静态空路线仍实时查询用户词典及方案置顶列表，避免漏掉新学习或手动加入的词。这个存在性索引不参与排序、不缓存最终答案。词典扫描逐行进行，避免同时展开大词库占用内存。

执行顺序先检查包含匹配置顶词的路线，再检查包含学习词的路线，最后检查其余系统词路线。取得置顶结果后，不再查询无匹配置顶的路线；取得学习结果后，不再查询既无匹配置顶也无学习词的路线。这是按同一跨路排序规则剪枝，每次按键都会重新读取用户状态，不缓存排名。

神韵翻译器在无辅码、无独立形辅约束的内部试查中，省略不显示的形辅提示反查；有辅码时仍执行完整筛选。不把「×是」筛选移到词长平衡、置顶、学习优先或首选后置之前，因为提前删候选会改变分批预取范围和后置位置，无法保证标准词码上的原排序。过滤器顺序保持不变。

单字路径所需的占桶查询找到首个有效单字后立即返回，空桶仍遍历至结束。词长平衡保留原有每批 120 个候选的预取范围，每批只读取一次各候选的文本，并按消费者需求逐页计算补位；内部查询只读取前部菜单时，不再预先重排后续所有页。这些优化同样用于普通输入，不改变标准菜单的候选范围和排序，不增加候选排名缓存。

内部试查不生成不会显示的预编辑文本和形辅标签，仍保留声声候选类型以及实际辅码筛选。用户词权重查询按规范音节码复用完整查库结果，同音词分别保留其最大权重，空结果同样复用；沿用调用方原有的缓存生命周期和学习后失效机制，不缓存最终候选排名。


已有确认片段、光标回补、反查及独立形辅输入沿用原有以词定字。没有符合条件的二字词时恢复原输入及选中项，沿用原行为：单字追加「是」，多字取末字。`[`、`;`、`/` 的语义不变。

本地验证使用 `texlua spec/append_shi.test.lua`、`texlua spec/select_character.test.lua`、后置相关 Lua 测试及 `bun test ./scripts/generate-append-shi.test.ts`。真实方案测试在 GitHub Actions 的 `adaptive_append_shi` 部署中运行，不能用静态生成结果代替实际候选验证。旧的机械追加「是」研究及 benchmark 不能直接当作此功能的评测结果。

## 性能诊断（2026-11-27）

鹮道 `b]` 的只读上屏基准仍未通过 50 ms 门槛。`d5fc764` 的正式重复输入 P99 为 60.41 ms，`8b5f8bc` 为 70.51 ms；不同运行有环境波动，不能据此宣称后一轮改动提速。`d656743` 的鹮道定向功能验证通过。

`40a47a2` 的分路线诊断显示：五条标准词码的菜单生成各约 7–14 ms，首个匹配词只需扫描 1–2 个候选，扫描约 0.01–0.03 ms；优先级预查约 0.12–0.15 ms。主要开销发生在标准菜单生成，而非末字匹配。诊断采用 CPU 时间，与端到端墙钟延迟不同；开启诊断的运行不作为正式性能门禁结果。

空用户库跳过学习排序整批预取的实验 `8356d79`，正式重复输入 P99 为 72.67 ms，没有可确认的收益，已撤回该快速路径。尚不能宣布性能问题解决；继续优化应测量标准翻译器及各过滤器内部开销，保留学习、置顶、后置和词长平衡语义。
