# 多方案长语料评测

`pwsh -File scripts/experiments/benchmark-long-corpus.ps1` 在本机隔离目录中直接调用 librime DLL，默认同时运行两个低优先级方案进程。Mira 回归仍只在 Actions 运行。语料来自 `output/append-generalization/corpora.json`，先用 `prepare-append-corpora.ts --download` 准备；默认组合原 5500 字与固定抽样的 36,235 字，不重新随机抽样。

采集复用单字验证的逐键前缀观测：每条请求向前输入，保存沿途完整候选及提交结果；遇到提前上屏即停止，整条请求标为未完成，不把尾段候选当作完整输入。重合前缀出现差异立即失败。各方案独立进程、独立缓存根目录和编译副本；不在同一 librime 实例中并发会话调用。路径仍按现有生成器枚举，多读音、辅助码、固顶、结构略码及词长直选保留各自规则；先最少选重，再最少物理按键，不能称为所有可能输入中的绝对最短。

候选缓存以部署文件、DLL、查询实现的摘要隔离，并用排序后的显式开关摘要区分文件。清韵长文评测采用 `character=false` 的字词模式，不能混用单字报告的 `character=true` 观测。每次计算仍独立抽查缓存首尾样本。中断后的完整 JSONL 记录可复用，残缺末行跳过后重新采集；旧格式缓存只允许由显式审计过的只读入口使用。

资源限制为工作进程合计工作集不超过 4 GiB、系统可用内存至少 8 GiB；低于 11 GiB 时不启动新进程。每 500 ms 左右采样，属于采样保护而非操作系统硬限制。长文候选生成周期性请求垃圾回收。外部方案生成在同一工作进程执行，清风版官方码表导出工具的短时子进程不计入工作进程峰值，系统可用内存检查仍覆盖整机。可以用 `-Parallelism 1` 串行；用 `-Schemes` 指定重跑范围。失败时调度器终止本次其余工作进程并报错，不输出成功汇总，已写候选保留供续跑。

```powershell
$env:RIME_DLL = 'F:/Input_method/Rime/weasel-0.17.4/rime.dll'
$env:RIME_SHARED_DATA = 'F:/Input_method/Rime/weasel-0.17.4/data'
pwsh -File scripts/experiments/benchmark-long-corpus.ps1 -Parallelism 2
bun scripts/experiments/summarize-long-corpus.ts
```

全部路径 TSV／JSONL、候选缓存、编译缓存、日志、资源记录和汇总写入已被 Git 忽略的 `output/corpus-benchmark-current/`，不提交大语料或详细切分。每个方案独立保存结果，可以按方案续跑。汇总必须集齐十二方案且语料摘要一致，验证字符覆盖与按键加总，再分别提供各方案覆盖和十二方案共同片段的成绩；排除片段完整保留。纯汉字连续片段以非汉字分界，最长 80 字；标点成本未纳入，因此 5500 字对照不等同于正式混合文本报告的总键数。

`mueaa/` 曾在冻结版本的「追加是」实验中出现首候选为「母」、实际提交「母a是」的反例。实验已剔除此路径并重算替代路径；这不是修改生产输入行为。普通评测的结构略码与尾字键均通过 `committedText(input) === word` 检查后才进入切分池；追加字反事实实验也必须保留最终实际提交验证，不能只凭前缀首候选放行。

## 2026-11-26 初次结果（四拼已由下节更正）

十二方案均完成原 5500 字与固定抽样 36,235 字的纯汉字段评测。新增语料的十二方案共同覆盖为 36,135 字，另外 100 字所属片段至少被一个方案排除；各方案自己的排除清单完整写入结果。共同片段均键：冰雪兰道 1.70926、冰雪莲道 1.71939、冰雪键道 1.72420、冰雪兰拼 1.72979、冰雪三拼 1.74305、冰雪鹮道 1.77603、冰雪鹤拼 1.78326、冰雪鹤道 1.78348、冰雪四拼 1.78633、声笔小鹤 1.86977、冰雪清韵 1.99640、小鹤音形（清风版）2.21284。这里比较按键数，不将方案间不同选重次数等同为相同操作负担。

调度记录累计约 58.8 分钟，含一次资源日志读写锁冲突后的缓存续跑；峰值工作集约 3.83 GiB，最低系统可用内存约 10.84 GiB。资源日志已改为临时文件替换与重试。TSV／JSONL 切分明细合计约 69 MiB，位于 `output/corpus-benchmark-current/`，已被 Git 忽略。`summary.md` 含总键数、均键、功能键和词长分布；`summary.json` 另含覆盖、排除、输入与缓存摘要。

当前生产配置的 `mueaa/` 实测提交为「母a了」，并非「母了」。本次修正的是评测不再误纳这类路径，未修改输入法生产行为；历史「追加是」实验中对应的「母a是」反例仍成立。


## 四拼单字编码更正

原语料生成器把三键音节直接接笔画，错误生成 `mueaa`，也漏掉补 `o` 和部分部件入口的合法路径。现与单字评测共用 `productionCharacterCodes`，删除旧分支；这属于评测生成器错误，不是输入法追加键故障。

在 `bed395f` 的生产数据上仅修正生成器重算：四拼 36,235 字全部覆盖、无需选重；十二方案共同覆盖为 36137 字，四拼 63601 键、均键 1.76000。含标点的正式 5500 字四拼总键数由 9685 更正为 9620；5000 字由 8783 更正为 8719。其他方案正式报告的总计逐项不变。纯汉字段 5500 字由 9294 更正为 9228，与含标点报告的差额口径不同。

重算来源、原结果备份和缓存位于 `output/sipin-production-fix/`；更新后的长文汇总与明细仍位于 `output/corpus-benchmark-current/`。方案标识迁移后的当前仓库保留迁移结果，报告 JSON 也保留现有 schema_id；没有混用迁移前后的生产输入。此前追加字实验的四拼排名使用旧候选池，不能作为修正后的结论，需另行重算。

隔离空词典复查：`muuo/ → 母了`、`mueo/ → 毪了`、`mueoaa/ → ⺟了`、`mueaa/ → 母a了`。合法编码不保证目标字是当前首选；词典包含母的低权重 mu2 读音，必须继续依据真实候选名次与提交检查。
