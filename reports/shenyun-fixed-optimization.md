# 神韵 R9 固顶受约束选优报告

本报告记录 `R9-21X21-M40-02` 映射下的一码、二简、630 与单字固顶现状。
公开方案只用于判断字词是否值得占用短码；最终码位始终按神韵 R9 的
21 个主键、5 个互斥辅键和当前候选规则重新计算，不机械迁移旧布局编码。

## 输入与边界

- 原始语料共 5,037,624 条；采集报告解析 11 个来源，其中 `snow-current`
  是本仓当前产物，在选优证据中排除，避免固顶结果给自己投票。
- 精简证据包含 132,040 条 1～3 键记录、48,709 个当前词典可用字词，
  来自 10 个外部来源、7 个独立家族。
- 龙码“无辅文件”只作为全码库存留在忽略的候选库，不进入常用度投票。
- 龙码整句包中的四码全码仍保留在候选库，但不把“存在于大字词库”误当成
  “值得占 1～3 键”；龙码工作簿的一、二级简码直接进入强证据。
- 同源的冰雪、星空、星猫、天行与 Eosphoros 只计作一个键道家族；原始
  来源数只作为弱的次级信号，防止 fork 数量灌票。

## 选优原则

1. **编码合法**：候选必须由当前 R9 音码、声调或形码规则自然得到。
2. **空间完整**：21 个一码、64 个二简、377 个 AA 单字以及两个 630 空间
   必须满足各自的完整性约束。
3. **按现行布局让位**：R9 有 382 个不同音码；二简占用 59 个天然空位和
   5 个最低权重音码，不沿用旧布局的空位清单。
4. **独立共识**：优先看独立方案家族数，再看来源数、原表候选次序和本仓词频。
5. **肌肉记忆成本**：现有码位有保留加分；630 的门槛最高，避免局部收益引发
   大面积迁位。
6. **整体协调**：一个字词只占一个前缀链位置；上层升级后，下层必须补入新的
   合法候选，禁止父子码重词。
7. **避免冗余**：已有结构略码、完整码稳定首选或等长/更短替代路径时，不再
   浪费固定简码位。

## R9 迁移结果

### 二简空间

R9 重新计算二简空间后，64 个码位中有 61 个码位和候选保持不变。三组退出与
新增码位如下；同一行只表示空间骨架的对应变化，不表示两个词之间存在迁移关系。

| 旧布局退出码位 | R9 新增码位 |
|---|---|
| `le→来说` | `lq→恋爱` |
| `te→同时` | `tq→天气` |
| `xq→需求` | `xw→形成` |

旧报告中的 `gp→公平`、`mm→慢慢`、`xr→显然` 不再属于现行二简表；在 R9
中 `gp`、`mm`、`xr` 都是有效音码，AA 单字分别为“宫、忙、需”。原证据选优
保留下来的 `rb→日本` 与 `zc→再次` 仍在二简表中。

### 630 与常用词路径

- 三拼 630：105 个两键槽＋509 个有效三码槽。
- 键道 630：105 个两键槽＋525 个三码槽。
- “一些”没有丢失：当前为三拼 `yii→一些`、键道 `yi→一些`；旧报告中的
  `fi→一些` 已不成立，当前 `fi→这些`。
- 所有码位都由同一布局感知编译器重新求值；旧版候选只作为肌肉记忆偏好，
  不能覆盖 R9 的合法性、去重和替代路径约束。

### 单字空间

- 377 个 AA 单字与 64 个二简完整覆盖 21×21 的 441 个主键对。
- “几”的现行 AA 音码为 `jk`；键道三码补位“急”为 `jku`。旧报告中的
  `jp→几`、`jpu→急` 属于旧布局编码，R9 中相应位置为 `jp→见`、`jpu→简`。
- 键道另有 1,589 个三码单字。

## 完整性与回归结果

当前生成器核验结果为：二简 64；AA 单字 377；三拼 630 为 105＋509；键道
630 为 105＋525；键道三码单字 1,589。选优期间排除了 16 个可用结构略码的
候选；完整码稳居首选筛选为 0，最终不存在等长或更短的冗余固顶。

批量验证另确认：

- `snow_sanpin.fixed.txt`：1,102 个全局唯一码位、1,132 个固顶候选。
- `snow_jiandao.fixed.txt`：2,681 个全局唯一码位、2,681 个固顶候选。
- 冻结映射快照覆盖 421/421 音节，映射 SHA-256 为
  `cef4fa7d303739e432d007331eb2028a241135e2d1c89a81772c14a4a619c6f2`。

在 `scripts` 目录复现核验：

```powershell
bun run fixed:check
bun run fixed:verify
bun run test:corpus
bun run typecheck
```

只有公开候选语料发生变化时，才需要先运行 `bun run corpus:evidence` 重建精简
证据；普通 R9 映射或固顶复核不应无条件刷新证据来源。
