# 神韵固顶受约束选优报告

本轮把龙码简码资料并入公开候选语料后，对神韵的一码、二简、630 与单字
固顶做了全空间重算。结果不是照搬任何方案的键位，而是把外部方案当作
“这个字词是否值得占短码”的证据，再按神韵自身的 21 主键＋5 辅键重新编码。

## 输入与边界

- 总语料：5,037,624 条；公开来源 11 个，独立家族 7 个。
- 精简证据：132,040 条 1～3 键记录，48,709 个当前词典可用字词。
- `snow-current` 被排除，避免现有固顶给自己投票。
- 龙码“无辅文件”只作为全码库存留在忽略的候选库，不进入常用度投票。
- 龙码整句包中的四码全码仍保留在候选库，但不把“存在于大字词库”误当成
  “值得占 1～3 键”；龙码工作簿的一、二级简码直接进入强证据。
- 同源的冰雪、星空、星猫、天行与 Eosphoros 只计作一个键道家族；原始
  来源数只作为弱的次级信号，防止 fork 数量灌票。

## 七项最终选优原则

1. **编码合法**：候选必须由神韵当前音码、声调或形码规则自然得到，禁止旧码硬迁。
2. **空间无损**：21 个一码、64 个二简、377 个 AA 单字以及两个 630 空间必须完整。
3. **单字优先**：二简固定沿用 53 个天然空位＋11 个极冷音码，不抢占 `fx→有`、`xl→需` 等高价值音码。
4. **独立共识**：优先看独立方案家族数，再看来源数、原表候选次序和本仓词频。
5. **肌肉记忆成本**：现有码位有保留加分；630 的门槛最高，不能因局部分数造成整片迁位。
6. **整体协调**：一个字词只占一个前缀链位置；上层升级后，下层必须补入新的合法候选，禁止父子码重词。
7. **可复现可审计**：大语料留在 gitignore；版本库只保存精简证据、算法、结果和本报告，生成两次必须一致。

## 本轮变更

### 二简

| 码位 | 原候选 | 新候选 | 1～2 键独立家族证据 | 龙码二简 | 判断 |
|---|---|---|---:|:---:|---|
| `gp` | 股票（1） | 公平（4） | 1 → 4 | 是 | 更通用的日常抽象词，跨方案一致性更强 |
| `mm` | 密码（0） | 慢慢（4） | 0 → 4 | 是 | 高频口语副词，适合作为固定短码 |
| `rb` | 日报（1） | 日本（4） | 1 → 4 | 是 | 使用面和跨方案共识均明显更高 |
| `xr` | 信任（0） | 显然（3） | 0 → 3 | 否 | 高频连接/判断副词，公开方案一致支持 |
| `zc` | 字词（1） | 再次（4） | 1 → 4 | 是 | 通用频率和跨域性显著提升 |

这五个码位本来就属于神韵二简空间，不新增被牺牲的音码。尤其没有把
`一些` 强塞进二简：它的自然两首键是 `fx`，而 `fx` 是“有”的完整音码；
当前 `fi→一些` 的键道 630 固顶继续保留，因此常用词可达性没有丢失。

### 630 联动补位

- 键道：`moo 慢慢 → 名字`。
- 三拼：`maa 慢慢 → 目的`，`rua 日本 → 日子`。

“慢慢、 日本”提升到二简后，原 630 位置按全局不重复约束自动补位。
除此之外，两个 630 均保持原码位；没有采用会导致“医院＋因为”变成
“因为＋方面”之类连锁洗牌的局部贪心结果。

### 单字

- AA 音码 `jp`：`既 → 几`。在 1～3 键证据中，“几”覆盖 6 个独立家族，
  “既”覆盖 3 个；“几”也是更基础、更适合作为无辅码首选的单字。
- 键道三码 `jpu`：原“几”上移后补入“急”。三拼没有三码单字区，因此
  只发生 `jp` 的共享 AA 更新。

一码冠军没有变化。受约束重算确认原有 21 个一码仍是各首键下兼顾频率、
公开共识与习惯成本的更优组合。

## 完整性结果

- 二简：64/64；其中 53 个天然空位、11 个极冷音码让位，空间骨架不变。
- AA 单字：377/377；与二简合计完整覆盖 21×21 的 441 个主键对。
- 三拼 630：105 个两键槽＋523 个有效三码槽。
- 键道 630：105 个两键槽＋525 个三码槽；键道三码单字 1,620 个。
- 两张表均满足全局一码位一候选、无父子码重词、所有固顶码可由当前布局导出。

复现命令在 `scripts` 目录执行：

```powershell
npm run corpus:evidence
npm run fixed:generate
npm run fixed:check
npm run fixed:verify
npm run test:corpus
npm run typecheck
```
